Idle Control Lab manual

Follow one edit from a Rust parameter to a change in prediction, then to a path through phase space.

1. Make one edit you can predict

  1. Open Neural dynamics, choose Idle engine, and pause around 3 seconds into the A/C cycle. The reference, trained and edited engines start at the same 750 RPM.
  2. In Network layout, choose Y axis. Select the output node labeled RPM/s to choose its bias. Selecting a connection chooses its weight. The X and Y markers match the coordinate menus.
  3. Keep the default Y coordinate, Output bias. Move its offset to +0.25. At identical inputs the network now predicts exactly 200 RPM/s more acceleration. The network’s output scale is 800 RPM/s per unit. As the edited engine gains speed, its RPM input changes, so the acceleration difference can change too.
  4. Watch the orange point move on the loss surface and the orange engine trace separate from the dashed trained trace. The whole event is recomputed from its original state, at the same playhead. Drag either plot to rotate it. Use the time slider to inspect a particular instant.
  5. Choose Restore trained values. The edited loss returns to the trained loss and the two prediction traces coincide.

2. Read the axes before reading the shape

Loss landscape. The horizontal coordinates are offsets in two selected weights or biases. Height is mean squared error (MSE) on the training examples. Every other coefficient stays at its trained value. The ring marks the trained network, and the filled point marks your edits. The displayed grid samples 25 × 25 pairs over ±0.8. The readout evaluates your exact slider values. Selecting a new axis resets both offsets so that the trained comparison stays on the same slice. The baseline is the best training checkpoint observed in this run.

Engine phase trajectory. The three coordinates are actual RPM minus target, RPM/s, and time. The time axis separates visits to the same RPM error. Each point describes a moment in an event. The resulting line is a projection of states that also include manifold torque, delay history and controller memory.

Hamiltonian phase trajectory. In spring–mass mode the coordinates are position q, momentum p, and energy H. The translucent mesh is the edited H over the training domain. The three paths use their respective energy functions. All use H(0,0) as the zero reference. The renderer scales each axis independently, so compare physical readings and loss values across views.

3. Follow the data through the engine

The physical reference computes acceleration from net torque and inertia. The ordinary network learns that same acceleration mapping from synthetic labelled operating points. Its three inputs are RPM, delivered air torque and accessory torque. Instantaneous throttle alone would leave out the air delay. During replay the physical reference alone drives the PID and manifold, using settings saved on the idle-simulator page. The PID bench separately closes the control loop around each candidate controller.

The replay uses 10 ms steps and saves a frame every 40 ms over 12 seconds. In the A/C event the 10 N·m load turns on at 2 s and off at 7 s. In the throttle event an 8% pulse lasts from 2 to 2.6 s. Learned rollouts can leave the training range after large edits. Treat their behavior there as extrapolation. The neural replay models running-engine speed dynamics; the full idle bench includes the separate low-speed stall latch.

4. Try the same edit in an HNN

Select Spring–mass. Set Y to Output bias and try +0.25. You have added a constant to the scalar H. Its derivatives, the predicted trajectory and the loss all stay the same. The surface is flat along that coordinate. Now select H1 · hidden bias for Y and repeat. That bias changes the slopes of H, so the motion can change.

H(q,p) = Σ vⱼ (wⱼq q + wⱼp p + bⱼ)² + bₒ
dq/dt = ∂H/∂p             dp/dt = −∂H/∂q

The training labels are state derivatives for a 1 kg mass and a spring of 1 N/m. The square activation gives the network a family of quadratic Hamiltonians that contains this oscillator exactly. Its very low held-out error measures a fit within that family. It does not establish performance on engines or nonlinear pendulums. RK4 advances the learned continuous-time field, so finite-step energy drift is possible. For a driven, damped engine, a Hamiltonian model would need inputs and dissipation or a broader system boundary.

5. Walk through the Rust code

Build examples and evaluate the network

src/network.rs defines dataset, evaluate, gradient and Fit::train. The idle dataset samples 475–1375 RPM, 6–58 N·m delivered torque and 0–12 N·m accessory load. Inputs are scaled around 750 RPM and 20 N·m. The HNN samples q and p independently in [−1, 1] in the stated SI units. Each model uses 112 training examples and 192 held-out examples from a second deterministic seed.

parameters of one hidden unit = [input weights…, hidden bias, output weight]
idle: 4 × (3 + 2) + 1 = 21 parameters
HNN:  4 × (2 + 2) + 1 = 17 parameters

The idle learner accumulates v * z.tanh(). The HNN first accumulates v * z * z into H, then forms its field directly in Rust:

field[0] += 2.0 * v * z * u[1];  // ∂H/∂p
field[1] -= 2.0 * v * z * u[0];  // −∂H/∂q

Optimize a baseline

Fit::train seeds the parameters and runs 900 full-batch Adam updates. It compares training loss every tenth update and keeps the best checkpoint. For idle, the model minimizes the squared acceleration error after division by 800 RPM/s. For the HNN, it minimizes the mean of the two squared derivative errors in normalized units (1 m/s and 1 N). Held-out RMSE is reported in RPM/s for idle and normalized derivative units for the HNN. Held-out examples never determine the checkpoint.

Change a weight and trace its consequences

network-diagram.js lays out the weights and biases in the order used by the Rust model. Picking a connection or node supplies the same parameter index as its menu entry. The signed number beside a selection shows its offset from training.

src/lib.rs owns Lab. Lab::slice copies the trained parameters, replaces two coordinates, and evaluates training loss for each mesh vertex. lab_edit handles a live slider event. It adds both offsets to trained values, recomputes exact losses and rebuilds the trajectories. src/motion.rs contains the torque balance integration and fourth-order Runge–Kutta integrator. neural.js reads Rust’s numeric buffers, projects the 3D coordinates and draws them. The packaged Rust desktop shell lives in desktop/src/main.rs.

Reproduce the checks

cargo test --release -p idle-neural
node --test
./script/build-neural.sh
./script/build_and_run.sh --verify

The Rust tests compare analytic training gradients with finite differences, sample a loss slice against exact edits, check energy-offset invariance and follow conservation over a rollout. The JavaScript tests exercise the idle controller, A/B benchmark and PID search. The offline browser entry is neural.html. Its checked-in WebAssembly can be rebuilt from the same Rust crate.

6. Compare control strategies

On Idle simulator, select Compare A/C strategies to hold gains fixed while switching load feedforward. Select Optimize gains to hold the strategy fixed while searching P/I/D. Both use three repeatable events. Inspect RPM, valve command, or the phase trajectory for an individual event before applying a proposal. The PID benchmark score trades RPM error against valve movement. The neural MSE measures prediction error on examples. Each optimizer answers its own question.
